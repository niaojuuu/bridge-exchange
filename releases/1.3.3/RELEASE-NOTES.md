## 1.3.3 — 2026-11-06

### 变更
- 修了管理员的“Claude 账号”一直显示“加载中…”。原因是某个账号下有会话的 Claude Code 进程不再回应（armsrv 上 11-06
  遇到：进程恢复会话后就不再读自己的输入），查这个账号的用量会一直等它，整个账号列表出不来，`/usage` 也可能这样卡住。
  现在服务发给会话进程的每个请求都有时限（一般 15 秒，带“用量去向”扫描的 2 分钟）：活进程不回应，就改用临时探测
  （最多 30 秒），还不行就在这个账号上写明原因，不再拖住整个列表。
- 同一个账号同一时间只查一次用量：同时开着几个页面或连点刷新，共用一次探测。以前每次各起一个进程，卡住的进程一结束，
  积压的查询会一下子起几十个。
- 打断（停止按钮、取消、看门狗）没有回应时，服务直接结束那个进程：这一轮记为失败（`turn.failed`，reason `unresponsive`），
  会话回到可用状态，下一条消息起新进程。以前打断也会一直等，看门狗停不下卡住的回合，会话一直显示在运行。日志里对应的警告是
  `process does not answer; ending it` 和 `account usage: a live process did not answer; probing instead`。

### 部署影响
- 无。

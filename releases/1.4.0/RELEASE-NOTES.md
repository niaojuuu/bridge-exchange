# claude-agent-bridge 1.4.0

提交 2b27791df18b217cd5b8b2fce1462a68c2f959ce

## 1.4.0 — 2026-11-06

### 变更
- 通知：会话完成（Claude 答完了，或者出错停下；后面还有排队的消息就等它们也做完）、会话因为 Claude 额度不够在等时，
  提醒会话的主人。每个用户（和管理员）在控制台左边的“通知”里自己选：在开着的控制台页面上念出来（浏览器的语音），
  和/或发邮件到自己填的地址（默认只在没开着控制台页面时发）。邮件从管理员在同一个对话框里设的“发信邮箱”发出：
  公用邮箱就行（QQ、163、Gmail……，填邮箱账号和它的授权码，常见邮箱自动填好服务器），授权码保存后不再显示。邮件只写会话名、目录、状态和打开它的链接，不带对话内容；
  同一个会话同一种通知一分钟最多一封，每人每小时最多 30 封。项目里的角色会话不通知。设置里可以试听、发测试邮件，
  看上一封发没发出去。
- 部署方能查“有没有人在干活”了（`to-bridge/0002`）：`GET /admin/busy` / `claude-agent busy`（管理员令牌，退出码 0 没人、
  2 有人）。整个实例的所有会话都算，不受 `admin_view_*` 影响，只给按原因、按用户的计数，不给会话名和内容；在提问、等后台子任务、
  回合在跑、等额度、有消息排队、回合结束后后台还在跑，都算在干活。
- 修了远程目录在服务重启或升级时断开、页面不再重连的问题（`to-bridge/0001`，1.1.0 起都有）：取连接票据时，反向代理在服务
  起来之前回的 502 / 503 / 504 以前被当成失败，现在和连不上一样按退避重连（1、2、4……最多 30 秒一次）。服务自己明确拒绝的
  （比如这台服务器不支持远程目录）照旧报失败。本机助手的重连本来就会重试，没有这个问题。

### 部署影响
- 约定第 2 节加了 2.6“有没有人在干活”（`GET /admin/busy`、`claude-agent busy` 和它的退出码），第 6 节第 5 步改成用
  `claude-agent busy`。`users ls` 的 `running` 不含等额度、排队和后台在跑的会话，不再作为部署方的检查依据。
- 走 nginx 的部署，重启、升级时用户共享中的远程目录会自己重连了。但修复在页面代码里：**升级到这一版的那一次**，开着的页面
  还是旧代码，遇到 502 仍会停下（照旧请用户刷新页面、重新共享）；页面刷新成新版本以后的重启、升级才会自己重连。
- 不用改配置：页面语音直接能用；发信邮箱由管理员在网页上设（没有新的 `config.json` 字段或环境变量）。
- 数据目录多一个文件 `mail.json`（0600）：管理员设的发信邮箱，**含邮箱的授权码**。备份数据目录时它也在里面，按密钥对待；
  没设过发信邮箱就没有这个文件。约定第 2.3 节的文件清单加了它。
- 服务要能连到发信邮箱的 SMTP 服务器（出站，一般是 465 或 587；经出口代理时，代理要放行这个端口）。
- 新接口：`GET /notify`、`PUT /notify`、`POST /notify/test`、`GET /notify/stream`（SSE，和会话事件流一样，反向代理不能
  缓冲）；管理员用的 `GET` / `PUT` / `DELETE /notify/mail`、`POST /notify/mail/test`。新错误码 `email_unavailable`、
  `too_soon`（409，命令行退出码 7）、`mail_failed`（502）。
- 数据库：加了一张表 `notify_settings`（每人一行通知设置），只加表，旧版本照常打开。

## 为什么

2026-11-06，armsrv 上管理员的“Claude 账号”一直停在“加载中…”。

- **起因**：一个会话的 Claude Code 进程恢复后就不再读自己的输入。服务查用量、打断时都在等它，而且没有时限，所以账号列表出不来，看门狗也停不下这个回合。
- **已临时处理**：用户同意后，bridge 在 06:05 UTC 只结束了那一个进程（PID 14520），没有重启服务。之后账号列表恢复正常。
- **1.3.3 的修复**：服务发给会话进程的每个请求都有时限。没有回应的打断会直接结束进程；没有回应的用量查询改用临时探测；同一个账号同一时间只查一次。以后再遇到这种进程，账号列表最多慢几十秒，不会卡死。

日志里如果出现 `process does not answer; ending it`，说明又遇到了这样的进程，服务已经把它结束了。方便的话把出现的时间告诉 bridge，我们想弄清 Claude Code 为什么会停住。

另外：`deployments/` 现在还是空的（见 0001），这次升级后请把 armsrv 的记录写上。
